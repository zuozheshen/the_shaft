# Terminal Visual Specification V1

这份规范记录固定台当前落地的显示参数，并为后续终端设计提供可对照的基准。实现以正式场景及材质为准。新配色、字体资源与其他设备的改造按对应 Issue 批准。

## 固定台的屏面

五块固定台屏面使用同一个 `ScreenSurface3D`。场景中的 Quad 决定尺寸、朝向和 UV。每个屏面复制自己的材质，再绑定对应 SubViewport 的纹理。主台视频与 CASE、左台资料、右台摘要与数字各有独立视口。

| 屏面 | 视口与 Quad 本地尺寸 | 显示 Profile |
| --- | --- | --- |
| 主台监控 | 320×240，1.44×1.08 m，4:3 | 视频用 nearest。曲率 0.015、扫描线强度 0.04、暗角 0.08、亮度 1.1。对白使用独立透明 2D 视口，在视频效果之后用未变形 UV 合成。 |
| 主台 CASE | 512×64，1.024×0.128 m，8:1 | StandardMaterial3D 使用 nearest，底色与发光绑定同一纹理。发光强度沿用 1.18，无曲率与扫描线。 |
| 左台档案 | 1152×648，2.48×1.395 m，16:9，随后受左台根缩放 | 独立 CRT 材质，曲率 0.006、扫描线强度 0.025、暗角 0.04、亮度 1.0。沿用现有 nearest 和 shader 的 240 行调制基准。调制强度按屏幕采样衰减，不代表档案正文只有 240 行分辨率。 |
| 右台信息屏 | 960×324，1.8744×0.630 m，随后受右台根缩放 | 无光照 LCD、linear。深灰绿底 `#0C1712`，浅灰绿摘要 `#BDCFA8`，字号 27。反馈有独立底区与较亮文字，字号 22。 |
| 右台数字 LCD | 576×96，1.1333×0.190 m，随后受右台根缩放 | 无光照 LCD、linear。原灰绿 LCD 底，深色数字，字号 68、右对齐。 |

主台的 `crt_screen.tres` 与左台的 `left_archive_crt.tres` 使用同一个 CRT shader 和不同参数。CASE 的材质定义在舱场景。设备之间只共享呈现接口，视口启停、选台、档案内容、灯和动作仍由现有控制器负责。

## 色彩、字体与状态

- 固定台沿用低饱和灰金属、深色屏底和浅灰绿正文。左台背景 `#0C1712`、正文与标题 `#BDCFA8`、次要状态及提示 `#819774`、分区底 `#142019`、分区边线 `#51684C`。CASE 使用深灰蓝底 `Color(0.045, 0.055, 0.065)` 和浅灰绿文字 `#BDCFA8`。此表是源色值，实机结果受发光、屏面和后处理影响。
- 左台使用现有 SystemFont 顺序 Consolas、Cascadia Mono、Noto Sans Mono CJK SC、Microsoft YaHei UI，并依赖系统字形回退。视口内标题 24、正文 19、提示 16、访问状态 14。CASE 视口内字号 24，沿用现有 Godot 字体及回退。视口内字号与最终屏幕上的字高要分别核对。使用有代表性的中文、多行混排、标点和 001 前导零检查缺字、换行和数字辨认。
- 优先级从标题、会话或关键值，到正文，再到来源、版本和次要提示。后续规格可沿用 PLAN v1.1 的深青文档色 `#102C2B`、浅色正文 `#D4E1D7` 和选中边线 `#A8C7B2` 做候选。先在实际视角检查字重与行距，再冻结字形、色值与最终像素高度。
- 选中用稳定底色或边线。焦点须能与选中区分，悬停和按下只给局部反馈。未读、可调阅和警告各保留自己的灯或文字提示。现有实体键、标识与颜色继续由对应场景管理。

## 后续设备的设计参考

右台两块显示均禁用 GUI 输入，无曲率、扫描线和闪烁。实体键与拨杆输入沿用操作舱射线和手柄焦点。右台沿用左台系统字体回退顺序。W 高密度文档的校准基准为已工作的 CanvasLayer。若有获批的 3D 文档呈现方案，先以无曲率、扫描线和色散的画面对照中文阅读与选区。阶段 1 的 720p 结果显示匹配屏口像素数仍可能使小字变软，后续方案需要用截图和真实操作重新确认。

## 实机检查

1. 在同一正式 `main_3d`、机位、窗口尺寸、渲染后端、FOV 和数据下取改动前后的完整截图和原像素屏口裁图。按 720p、1080p、超宽和用户实际窗口选择验证范围，在原始尺寸看字，放大裁图只用于定位原因。
2. 先检查主台 4:3 视频边界、CAM 两机位、CASE 字符与对白叠加，再检查左台系统日志、乘客档案、来源、版本、滚动和灯反馈，以及右台数字前导零、摘要末行与操作反馈。空舱以正式内容验证，资料和对白用现有预览或测试夹具复现。
3. 用实际投影尺寸、屏口角度和遮挡选择字号及视口大小。核对发光、采样、扫描线和全局后处理对细笔画的影响。发现屏口比例或小字问题时，在局部材质和视口中复现并对照。
4. 在 REVIEW 分别记录自动验证、Godot AI 场景和截图、用户实机阅读与操作验收。
